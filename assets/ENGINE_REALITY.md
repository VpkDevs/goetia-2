# Engine Reality Check

Verified against the code on 2026-07-21, not assumed. Re-verify with the
commands at the bottom if the engine changes.

## What the engine can display today

| Surface | Status |
|---|---|
| Image decoders (PNG/JPG/etc.) in the dependency tree | **none** — `grep '^name = "(image\|png\|jpeg-decoder\|zune-png)"' Cargo.lock` → 0 hits |
| Mesh UV coordinates | **none** — mesh vertices are `pos: vec3` + `normal: vec3` only |
| Per-instance texture binding | **none** — `InstanceRaw` is `model`, `color`, `emissive`, `anim` |
| Textures that exist at runtime | HDR + depth targets, the bloom mip chain, and **one** UI font atlas |
| UI font atlas format | `R8Unorm` — **single channel**, built procedurally from a hardcoded 5×7 bitmap. No color. |

**Bottom line: the game can load exactly zero image files.** Every pixel you see
is generated by shader math over untextured primitives, plus GPU particles.

This is not an oversight — it is the stated art direction (primitives + flat
shading + emissive + bloom + vertex-procedural motion, no skeletal animation).
It already runs the pathological frame at 764 fps.

## The four tiers

Every row in `ASSET_INDEX.md` is tagged with one of these.

### Tier A — usable today, zero engine work
Nothing in the game world. Only the **font atlas glyph shapes**, and even then
you'd be authoring a 1-bit coverage bitmap, not an image.

### Tier B — small, contained engine change → unlocks all 2D
**This is the high-leverage one.** The UI pipeline in `crates/goetia_render/src/ui.rs`
*already* uploads a texture, binds a sampler, and draws textured quads. To use
real 2D art you need roughly:

1. `R8Unorm` → `Rgba8UnormSrgb` on the atlas texture.
2. An image decoder (`image` crate, PNG feature only) + a loader that takes a
   PNG atlas from disk instead of `build_atlas()`.
3. A second atlas binding (keep the font atlas; add an `icons` atlas), plus a
   `UiBatch::icon(rect, atlas_uv, tint)` call.

That is a contained change in one file plus one new dependency. It unlocks:
skill icons, sigil icons, status icons, item icons, rarity frames, boss
portraits, panel art, cursors — i.e. **most of what makes a game look finished**.

⚠️ **Contract note:** `crates/` is frozen per `API_CONTRACT.md`. Doing this is a
deliberate contract revision (bump the version, document it), *not* a casual edit.
Per `AGENTS.md` the correct move is to log it as a contract gap first. It is a
legitimate, well-scoped revision — just make it a decision, not a drive-by.

### Tier C — needs a real material pipeline
In-world 3D texturing: albedo/normal/roughness maps on enemies, props, floors.
Requires adding UVs to `MeshBuilder` output, a texture array or bindless setup,
sampler plumbing through `mesh.wgsl`, and per-instance material indices.

This is a **large** change that fights a look which already works. Recommended
verdict across the board: **don't**. Procgen wins here on both quality and cost.

### Tier D — outside the engine entirely
Logo, wordmark, Steam capsules, key art, itch.io banner, app icon, trailer,
screenshots, press kit. **No engine work at all.** These are pure real-asset
wins and are the single best place to spend your generation credits, because
they're what a buyer sees before they ever run the game.

## Recommended order of investment

1. **Tier D marketing art** — zero engine risk, highest commercial return.
2. **Tier B UI icons** — one contained change, transforms perceived polish.
3. **Tier A font** — cheap, optional, only if the 5×7 bitmap starts bothering you.
4. **Tier C in-world textures** — only if profiling and playtesting both say the
   flat look is failing, which right now they don't.
